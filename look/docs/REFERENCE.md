KEYBOARD SURFACES

Uppercase letters mean Shift + letter (R is Shift-R, D is Shift-D); lowercase
transport keys stay lowercase.
Key labels use cyan, ordinary labels are subdued; green indicates playback or
selection, amber indicates paused/partial/unavailable, purple indicates modes.
Colors supplement text and never carry the only indication of state.

LOOK files: H hidden, F sort, R rename, D delete, B desktop clipboard,
C Copy To, M Move To, T cut, P paste, L LO context, X clear working set,
Y path, G exit to directory. Hidden files default off; lh shows them.

Media Find: type filters or / enters search; ↑↓ or J/K move; Shift-↑↓ page; Shift-←→ ends;
Tab mark; A mark/unmark all visible; C clear selection; Enter/P play;
Q append queue; S save playlist; I info; V logical/all physical sources;
H hidden; X hide selected; D choose a containing directory to hide;
U remove matching hide rules; Esc finishes search, then clears query, then exits.
◆ is SHA identity and · is scanned identity; these are indicators, not keys.

LK MP: / enters search; Enter/Esc finish editing and retain the filter;
↑↓ or J/K select; Shift-↑↓ page; Shift-←→ ends; Tab mark;
A marks/unmarks all visible; C clears marks; Enter plays marks/current;
B appends marks/current to queue; D hides a directory;
L library; Q queue; space play/pause; ←/→ seek 10s; p/n previous/next;
s shuffle; r repeat; v opens visuals; x stop; Esc clears query then exits.
Both media screens allow arrows, Tab and selection actions during search.

LK Player: space play/pause; ←/→ seek 10s; p/n previous/next;
s shuffle; r repeat; v cycles nine ambient visualizers, large ASCII album art with a subtle shimmer, Cycle (all ten every 10s), and normal view;
x stop; q/Esc closes the view while playback continues.
Visualizers are ambient animations, not measurements of decoded audio.

Destination picker: ← parent (above filesystem root shows Fabric nodes);
→ descend; Enter chooses the highlighted directory (not the current directory);
↑↓ selection; Shift-↑↓ pages; Shift-←→ first/last; type filters;
Backspace edits filter; Esc/Q cancels. On remote roots Tab toggles common/all;
inside remote directories Tab returns to common places. Local views have no Tab mode.
Destination prompt: Tab completes local/remote paths and recent destinations;
→/↓ opens picker; ← edits the line; quote spaces when entering shell commands:
lcp "video.mp4" "@3090:/run/media/jreno/2TB Storage/srv/media/video/"
@node:~/ expands on the destination node, not on the initiating Mac.

ff [WORDS]: recursive filename search under this node's home, not Fabric search.
Results fill in while discovery runs; H includes hidden paths. Enter returns
through the normal LOOK file view. fznv opens a selected file in Neovim.
lk find QUERY: catalog filename/path/metadata/description/supported content search
across reachable paired Fabric nodes, with local fallback. Remote-only results
currently offer a node-qualified path via Y; they do not silently fetch bytes.

LO input: ↑/↓ recalls prompt history; ←/→ edits text; Ctrl-D exits;
Ctrl-C cancels the current request. Browser/CarPlay controls use media transport;
terminal transport follows the active supported player.

Downloads: default permanent ~/Downloads/LOOK; --holding opts into 30-day
retention in ~/Downloads/LOOK-Holding. Ctrl-C detaches; cancel is explicit.
--detach returns immediately; --json returns a receipt, not completed video.
keep moves a held download and its sidecar together and clears expiry.
Neighboring .info.json holds searchable source metadata; MP4 playback itself
does not require it. Manual moves should keep both if descriptions matter.
Existing LOOK-owned Downloads/Pictures roots are discovered on each node at
watcher startup and every five minutes. Completed LOOK downloads index immediately.
Configured desktop media apps apply to LOOK opens; protected Apple media may
require an authorized Apple player. File extensions alone do not establish DRM.

LOCAL SPEECH INPUT

# Local speech input

Speech-to-text is optional and separate from the existing speech output/voice
profiles. Audio stays on this computer. No microphone starts at installation,
startup or when a text field receives focus; transcription never executes words.

## Start here

Open Settings and search for **Local speech input**, or run:

```sh
lk transcribe status
lk transcribe setup
lk transcribe recording.m4a
lk transcribe recording.wav --output transcript.txt
lk transcribe recording.wav --note "Meeting notes"
lk dictate --note "Spoken notes"
```

Setup explicitly downloads dependencies into
`~/.local/share/look/transcription/venv` and caches Phonon-2 through Fermion.
Normal LOOK installation does not download this runtime or model. On the tested
Apple silicon Mac, the isolated runtime occupies about 1.3 GB, in addition to
model/cache storage. The Phonon-2 download is about 164 MB, unpacking to roughly
178 MB; it currently recognizes English. Its weights are CC-BY-4.0, derived from
NVIDIA Parakeet TDT 0.6B v3. See the [model documentation](https://www.fermionresearch.com/docs/speech-models/).

Setup fetches/verifies model files. A successful offline transcription verifies
inference separately; `status` only reports runtime/configuration presence.
File transcription explicitly sets Hugging Face/Transformers offline mode. A
missing model produces an error and setup instructions rather than downloading
silently. Network access is needed for initial setup, not routine inference.
First load/compilation can be slower than the actual decoding operation.

File input accepts WAV/FLAC/OGG/AIFF directly. Other media is converted locally
with ffmpeg to a temporary 16 kHz mono WAV; the original stays untouched.
Long files use the engine's chunking. No automatic source recording is retained.
`--output` creates a new UTF-8 file and refuses to overwrite an existing file.
`--note` creates a normal note in the Transcripts project with normal sync behavior.
Without either option, transcript text goes to standard output; `--json` returns
structured text and a note ID when one was created.

`lk dictate --note "Spoken notes"` names the new note before recording.
Ctrl-C finishes recording and returns captured text. In the Notes quick editor,
**Ctrl-D** starts dictation; **Ctrl-C** finishes and inserts text at the caret.
The draft stays editable until Ctrl-S/Shift-Enter saves. Uppercase D remains text.

Apple silicon uses Fermion’s live dictation engine. Linux and Intel Macs record
locally first, then transcribe after Ctrl-C; Linux setup uses CPU PyTorch wheels
by default rather than downloading CUDA libraries. A larger model is optional,
not required. Capture needs the optional speech environment even when a local
server provides transcription. Successful temporary recordings are removed; if
capture/transcription fails after audio was recorded, a private WAV is retained
under `~/.local/share/look/transcription/recovery/` for manual retry.

macOS may request microphone permission for your terminal; Linux needs an available PortAudio input device. This does not select
speakers, modify Bluetooth pairing or change the system audio output.
Microphone input has not been exercised by the automated tests.

## Replace the engine

The reusable Python entry point is `transcription.transcribe(path) -> str`.
Applications can adopt it without depending on Phonon-specific details. A local
OpenAI-compatible speech server provides an alternate file backend:

```sh
lk transcribe configure --server http://127.0.0.1:8000/v1 --model YOUR_MODEL
lk transcribe recording.wav
lk transcribe configure --model phonon-2
```

Configure without `--server` returns to the local Fermion CLI backend. Settings
live in `~/.config/look/transcription.json`. Alternate servers must use a loopback
HTTP address and expose `/audio/transcriptions`; LOOK does not launch the server,
install its model, guarantee its offline behavior, or send audio to remote nodes.
Uploads are limited to 32 MiB; use the file engine for longer recordings. On this
backend, microphone dictation records locally and sends the finished file to that
server.

CLI file/dictation capture, Notes output and Notes quick-editor insertion share
this interface. Signal/Albert microphone buttons are not included; those can
share this boundary without changing the storage/engine model.

WEB READING DESK

# The reading desk

`lk web` opens a personal Markdown home backed by a real Notebook note.
The rendered page shows headings, prose and numbered links. The selected link is
highlighted, with its full target below the page. Nothing is fetched until you open it.

- Up/down or Tab select links; Enter opens; 1–9 open directly; `l` opens the full link picker.
- Shift-up/down or Page Up/Down scroll the note; Shift-left/right jump first/last.
- **`e` edits the displayed note**, using the Notebook quick editor. Enter adds a
  newline; Ctrl-S or Shift-Enter saves; Escape cancels. Ctrl-K inserts links,
  including picking another note. Delete or move Markdown lines to remove/reorder links.
- **`n` chooses an existing Notebook note as your home**. Search by title/project;
  no copying IDs. Home selection is local; the note uses normal Notebook syncing.
- `a` adds a named web bookmark to the home note, regardless of which linked note
  you are reading. `y` copies the selected Markdown link. `r` selects related notes.
- `h` returns to home. Escape returns from a linked note, then exits at the root;
  `q` exits directly. File/Fabric links use the existing Notebook handlers. Explicit
  command blocks retain Notebook's review and confirmation before execution.
- `u` opens an address; `s` searches DuckDuckGo's HTML search. `b` cycles installed
  browsers and remembers the choice; w3m leads on fresh installs when available.
- `t` toggles initial numbering; `?` shows the browser guide. `W` opens a shell pane.

On first opening the desk, Web creates a **Web Home** note under project **Web**,
with Google News, a starter reading shelf and copies of legacy bookmarks. This
migration happens once; old bookmark data is retained. The note becomes the
editable authority: changing or removing starter links works like any other note.
A deleted/conflicted home is not silently regenerated; choose another with `n`,
or explicitly create a replacement with `e`. Resolve conflicts in Notes.

`lk web home` exports the selected home to local HTML and opens it in the chosen
browser. Its rendered text is escaped; only HTTP(S) links become browser actions.
Use the terminal desk for note, file and command links. The HTML is a generated
view, so edit the Notebook note rather than the exported file.

```sh
lk web list
lk web https://example.org
lk web search terminal art
lk web --browser lynx https://example.org
lk web --browser qutebrowser home
lk web --native-style
```

The picker discovers w3m, Lynx, Links/Links2, Chawan (`cha`), and qutebrowser.
It does not install them. Missing browsers are listed by `lk web list`; a machine
with none installed can still manage bookmarks and copy links from the desk.
The home-note selection, legacy bookmarks and chosen browser are local under
`~/.local/share/look/web/`. Existing browser bookmarks, sessions and keymaps
are not imported or replaced. Web home content is stored and synced by Notebook. The guide describes the browser's default keys;
personal keymaps may differ.

## Link hints

Lynx and Links launch with numbered links: type a number and Enter to follow.
Qutebrowser uses `f` and letter hints to open links. Chawan is a true terminal
browser with letter hints: `f`, type the letters, then Enter. Chawan's hint
alphabet can be customized in its own configuration. w3m supports Tab/Enter
and LOOK's number-then-Esc-j selection while tags are visible.

Qutebrowser is explicitly marked **graphical window**. It opens a normal
qutebrowser session, using your existing configuration; quitting or handing off
to an existing instance returns control to the desk. LOOK's generated home page
follows Paper/Neon/Slate/Custom, but qutebrowser's chrome and remote websites
keep their own styling. Terminal browsers have limited support for modern
script-heavy sites; select qutebrowser when you need its graphical web engine.

w3m and Lynx use terminal-default text/background with ANSI link colors. Links
uses a light or dark ANSI background according to the selected LOOK palette.
Color overrides last only for that invocation. `--native-style` keeps the
browser's appearance. LOOK does not rewrite personal browser files. The w3m
session overlay reserves Esc-h, Esc-j and normal Enter; other personal bindings
are copied from its configured keymap.

You can run `lk web` in LOOK's adjacent shell pane. Exit the browser to return to
the desk, then exit the desk to return to that pane's shell. Existing pane focus
and close shortcuts remain unchanged.

## Adjacent shell pane

Press **Shift-W** from the Web reading desk to open
a sibling shell in the current working directory. Your selection, filter and
scroll position stay in the original view. In Kitty, **Option-Shift-W** on Mac
(**Alt-Shift-W** on Linux) switches focus, and **Ctrl-Shift-W** closes the focused
pane. In tmux, **Ctrl-B then O** switches; `exit` closes the shell. These hints
remain visible after opening a pane. The terminal owns the sibling shell. New panes halve the active pane along
its longer physical dimension: wide panes split left/right, tall panes top/bottom.
Reported pixel geometry takes precedence; terminal cell proportions are the
fallback. Within the existing splits layout, only the selected pane is subdivided.

The views redraw to fit the terminal after panes open or close. Shift-W stays
ordinary text inside note editors and URL/bookmark prompts. In a launched web
browser, the browser owns its keys; quit back to the desk to use Shift-W.
Without Kitty or tmux, LOOK explains the requirement and stays in your view.

## Reading without link tags

Numbered browsers start with tags off. Press **t** in the desk to remember tags
on/off for future launches, or use `lk web --tags on URL` / `--tags off URL` for
an invocation override. This controls w3m, Lynx and Links/Links2; Chawan and
qutebrowser retain their native temporary `f` hints, cancelled with Escape.

In w3m, **Esc then h** toggles tags. Type a number, then **Esc then j** to select
that numbered link; Enter follows it and hides tags again. Tab and Enter continue
to work. These session bindings use a temporary keymap overlay, retain unrelated
personal bindings, and never save to the browser config. The default applies only
to launches through LOOK.

Lynx changes numbering through `o` → Keypad mode. Links/Links2 use Escape → View →
HTML options → Links are numbered. These are native menu controls: LOOK does not
claim automatic post-navigation clearing or a shared in-page key for them. The
desk shows each browser's guide.

Hiding tags removes numeric clutter, not site navigation. Removing menus, cookie
prompts and repeated headers requires content extraction; this update does not
implement an article-reader view. Terminal text browsers have different rendering
capabilities from a graphical browser or a browser-engine-backed terminal viewer.

## w3m navigation keys

Once a page opens, w3m receives keyboard input directly. LOOK does not translate
arrow or Shift-arrow sequences or override page/Home/End navigation. Native and
personal browser bindings remain in effect. The desk itself retains LOOK's
arrow/Shift-arrow navigation. Link-tag shortcuts remain available in w3m.

ARCHITECTURE DESIGN REFERENCE (NOT EXECUTABLE CAPABILITIES)

# Sharing a memory: item grants and a replaceable front door

Status: **architectural design, not implemented**. There is no guest-share
command, share-management interface or public guest gateway in this design update.
No public listener is enabled and no trust/configuration is changed.

Future Crash + LOOK is a personal computing environment spanning a person's
devices. Files, Notes, media and commands are useful surfaces within it. Sharing
adds one boundary: an owner may grant another person access to a particular item
without giving that person general access to the environment.

## Existing mechanisms and their limits

- Fabric trust authorizes paired nodes. A guest link must not create a peer,
  grant node trust, or authorize general node APIs.
- Signal has short-lived, process-local media tickets tied to particular media
  requests. These are playback mechanisms, not durable email-ready share grants.
- Existing media routes support source delivery and browser presentation.
  A source responding successfully does not prove browser playback works.
- Tailscale Serve is private to the tailnet. Funnel can expose a local service
  publicly. Public reachability alone does not authenticate a guest.

These facts do not imply that guest sharing is already available. Verify the
current implementation and live discovery before reporting operational capability.

## The smallest useful boundary

An **item grant** describes owner intent independently of network transport:

| Part | Meaning |
|---|---|
| Owner | Existing local/Fabric authority allowed to share the item |
| Item | One explicitly selected resource and its source identity |
| Representation | Original file or an explicitly identified browser rendition |
| Guest policy | Anyone holding the link, or a separately verified recipient |
| Lifetime | Creation, expiry and revocation state |
| Rights | Read/stream the selected representation; no browsing or mutation |

Reuse existing item identities and Fabric locators. A locator such as
`@node:/path` identifies a location, not permission. Before implementation,
resolve how moved/replaced files are identified: a share must not silently begin
serving a different file that happens to occupy the same path. Content digests
can pin a representation where available; do not invent a second Fabric namespace.

A human-readable title is presentation, never authority. A random grant/link
identifier must not expose local paths, node credentials or internal API URLs.
Treat a link secret as bearer authority, store a verifier rather than a reusable
plaintext secret where feasible, and avoid writing it to access logs.

## Guest delivery boundary

The public-facing service should offer only a small share page and bounded
read/stream routes. It validates the grant and serves its selected item through
existing private owner-authorized facilities. Guests cannot choose arbitrary
nodes, paths, catalog IDs or internal API operations.

Tailscale Funnel is a possible first **reachability adapter**. Alternatives can
publish the same guest service without owning grant policy, recipient identity
or Fabric trust. Keep provider addresses separate from the resource/grant;
transport replacement may change a URL without changing who owns the item.
Do not publish the ordinary Unified Node, Signal/Albert control APIs, or a whole
directory merely to share one video.

No gateway, adapter interface, grant schema or endpoint is implemented here.
Define those only when a concrete sharing feature is approved.

## Contracts a future implementation must demonstrate

1. Explicit item selection and review precede publication. Selecting a file or
   previewing a note never creates a share.
2. Every guest content request, including HEAD and byte-range requests, checks
   the grant, representation, expiry and revocation. A signed token alone cannot
   provide immediate revocation without authoritative state or a bounded expiry.
3. Revocation denies subsequent requests. Define treatment of an already-open
   stream honestly; it cannot retrieve bytes already delivered to a recipient.
4. Anyone-with-link shares can be forwarded. Recipient-restricted shares need
   actual recipient verification; an email address in a grant is not verification.
5. Browser video delivery preserves seeking and reports preparation/failure.
   MP4/MOV filenames alone do not prove that the contained codecs are supported.
6. Sharing read access cannot guarantee prevention of copying or screen recording.
7. An unavailable owner or source produces an honest unavailable response, not
   invented access or silent substitution of unrelated media.
8. Publishing, changing lifetime/access, and revoking are separate owner actions
   with observable receipts. Opening a share grants no further authority.

## How assistants should use this document

This is a design reference, not an executable tool definition. LO, Albert and
Signal may explain it when retrieved, but must not claim they can create guest
shares, generate working public links or revoke them. Do not advertise a
`share.create` capability until a registered, authorized implementation exists.

The content is included in the generated installed `look/docs/REFERENCE.md`,
available through existing file-reading tools and `lk doc` / `lk help all`.
Source documentation and runtime evidence have different roles: docs describe
contracts; registered tools and live observations establish what can run now.
